# Augur 本次更新说明

> 面向用户的功能说明（非技术变更日志，技术细节见 [CHANGELOG.md](../CHANGELOG.md)）。

## 这次更新解决了什么问题

用户实测反馈的"很多地方数据都不显示"，v10.16.5/v10.16.6 已经覆盖了首页和投委会/深度报告两块。这次（v10.16.7）继续把同样的实测排查方法用到 Dashboard 剩下的页面上（历史记录、组合优化器、持仓、自选股、扫描器、信号、设置、聊天），找到并修复了两个具体的"数据不对/不显示"问题。

## 修复内容

- **历史记录页（`/history`）的 52 周日历热力图一直没显示出来**：页面代码请求 `/api/history?page=1&per_page=365`，但接口的分页模式限制 `per_page` 最多 100，超过就返回 400 错误；前端这里用了一个空的 `.catch()`，把错误悄悄吞掉了，所以日历卡片从来没出现过，也没有任何报错提示。修复方法是换成接口本身就支持的"非分页"模式（`/api/history?limit=365`，上限 500），这个模式刚好就是日历功能需要的"最近 N 条记录"，不需要分页信息。
- **组合优化器（`/optimizer`）算出来的 Sharpe 比率、甚至最优持仓权重本身都是错的**：优化器内部用的是"每日收益率"，但传入的无风险利率是"年化利率"（比如 2%），代码直接拿年化利率去减每日收益率、再除以每日波动率——单位完全不匹配。每日收益率本来就很小（大约 0.1%-0.3%），被年化的 2% 一减，几乎所有股票都变成负的"超额收益"，这不仅让显示的 Sharpe 比率离谱（实测某组合算出 -1.44，但正确值应该在 +2 左右），更严重的是这个错误的数字直接参与了"最优权重"的计算公式，导致优化器给出的持仓建议本身就不可信。修复方法是把年化无风险利率换算成每日利率（除以 252 个交易日）之后再使用。修复之后又发现一个连带的小问题：页面上"预期收益""波动率"两个数字本来就是按年化显示的，但 Sharpe 比率显示的却是"每日"口径的数字，三个数字摆在一起单位不统一，看起来还是像在出错。这次一起改成 Sharpe 也按年化显示（乘以 √252），保证三个数字口径一致。

## 测试情况

完整测试套件 **2100 个测试全部通过**，没有失败项。

## 这次是怎么发现的

延续 v10.16.5/v10.16.6 的方法，但这次不是找"async def 卡死事件循环"这一类问题，而是把 Dashboard 剩下没检查过的页面挨个过一遍：把每个页面模板里所有 `fetch(...)` 调用对应的后端接口列出来，挂到本地正在跑的开发服务器上用真实股票代码逐个请求，看返回的数据是否报错、字段对不对、数值是否离谱。大部分接口都没问题，上面两个是确认存在的真实缺陷。

之前 v10.16.6 记录的"投委会/深度报告并发期间其他请求会卡顿几秒"（GIL 限制）这次没有再碰，按用户此前的决定继续保留现状。
