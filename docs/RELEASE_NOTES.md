## v10.10.0 — augur doctor 环境自检（2026-07-12）

排查本机环境问题一直靠"猜"——比如上一版开发过程中就真实踩过一个坑：某台机器的 Python 环境链接了 Apple 的 LibreSSL 而不是标准 OpenSSL，导致 yfinance 底层请求悄悄全部失败，却没有任何提示，只能一步步手动排查才能定位。这一版加了 `augur doctor` 命令，一次性检查这类环境问题：

- Python/SSL 工具链是否是已知会让 yfinance 出问题的组合（并给出修复建议）
- FINNHUB / Alpha Vantage / OpenAI / EDGAR 联系邮箱等可选配置是否已设置
- 各数据源（yfinance / finnhub / alphavantage / stooq）当前是否真的连得通
- 学习引擎积累了多少预测数据、有多少已经核对完成

不想联网检查就加 `--offline`。

## v10.9.0 — 可信度全面修复 + SEC EDGAR 真实数据（2026-07-09）

这一版没有新增炫目的界面功能，而是把"18位大师给出的分数到底有多可信"这个问题从头到尾修了一遍——从共识计算的底层逻辑，到学习机制是否真的在学习，到财报数据是不是真实的，全部过了一遍手，能验证的都用真实数据验证过。

### 共识计算不再被悄悄稀释一半

之前系统里有一个默认开启的"MetaModel"，会把 18 位大师精心加权后的分数，强行和一个简单中位数各占 50% 混合——相当于大师们的专业判断被砍掉了一半权重，而且这个 MetaModel 本身从未被验证过有没有用。现在默认权重归零，你看到的共识分数是真正反映各位大师权重差异的结果。

### 回测不再默认用假数据

Dashboard 的"回测"页面和 CLI 的 `augur backtest` 命令，之前默认跑的是程序生成的合成数据——看起来像真实回测结果，其实不是。现在默认改成真实历史数据，合成数据仍然保留，但需要显式加 `--demo` 才会用，而且会明确标注"这是演示数据，不计入排行榜"。

### 学习机制真正开始积累数据

Augur 从 v8 起就宣传"大师们会越用越准"，但这套学习机制实际上从未真正积累过数据——预测记录不会持久化，也没有定时任务去核对"当初预测的和后来实际发生的对不对"。现在预测会立即持久化，并且有定时任务自动核对到期的预测结果。今天开始用，大概 30 天后你会开始看到第一批真实的"预测准确率"数据。

### SEC EDGAR：真实财报，不再是简化比率

18 位大师原本看到的 PE、ROE、毛利率等指标都来自 yfinance 的简化计算。现在换成美国证券交易委员会（SEC）EDGAR 系统的官方财报数据（10-K/10-Q 里的真实数字），历史深度也从原来的约 2022 年拉回到 2011 年左右（视公司而定）。这不影响你调用 `augur analyze`/`augur consensus` 的方式，只是背后的数字更真实了。（仅覆盖美股/美股上市中概股，A股/港股/加密货币不受影响，继续用原来的数据源。）

同一批 SEC 数据还带来两个新信号，所有大师都可以选择性地参考：

- **内部人交易信号**：追踪高管/董事最近 90 天的真实公开市场买卖行为（不含 RSU 归属、税务扣缴等噪音），聚集买入会被适度放大。
- **机构持仓信号**：追踪伯克希尔、文艺复兴科技、桥水基金等知名机构的季度持仓环比变化。

### 新增（默认关闭）：AI 读财报，提炼管理层展望

新增 `augur guidance TICKER` 命令，用 LLM 读取公司最新 10-K/10-Q 里的"管理层讨论与分析"章节，提炼出管理层展望情绪（正面/负面/中性）、具体前瞻指引数字、风险因素变化。因为这一步会产生真实的 LLM API 调用费用，**默认关闭**，需要你自己设置 `AUGUR_EDGAR_GUIDANCE_EXTRACTION=1` 才会启用，且只在你主动调用时才会抽取（不会自动跑、不会推送）。

### 情绪分析修正

社交情绪分析里的"X（Twitter）"这一项，其实一直是无法访问真实 API 后留下的假数据占位符，但仍然占了 20% 权重参与打分。现在已经从计算里完全剔除，StockTwits 和 Reddit（两个真实数据源）按比例分摊了这部分权重。

### Regime 权重：验证后诚实下线

早期版本里有一套"牛熊市自动调整大师权重"的手工规则（比如"熊市里更信 Howard Marks"），这套规则的数字从未经过真实历史数据验证。这次用真实 SEC 数据跑了一遍跨越 4 年、37 支股票的样本外验证，诚实结论是：**没有观察到明显效果**。与其继续用一套未经验证的规则悄悄影响你的共识分数，不如直接停用——已经停用。

### 内部工程健康度

命令行工具（`cli.py`）从一个 1476 行的单文件拆成了 9 个按功能分类的模块，纯内部重构，不影响任何命令的使用方式。

## v10.0.0 — 正式公开发布（2026-06-29）

这是 **Augur v10** 的第一个正式公开版本。从 v8.2 到 v10.0，这是一次全面升级：

### 终端工作区（Bloomberg Terminal 风格）

`/settings` 页面新增了完整的布局系统，让你把 Dashboard 变成"自己的终端"：

- **4 套布局预设**：`analyst`（默认，全功能）/ `trader`（极简，快速出信号）/ `committee`（以投委会为核心）/ `minimal`（隐藏大多数导航项）。切换预设可以同时改变默认落地页、Ticker Tape 开关、隐藏哪些导航菜单项。
- **多套命名 Profile**：保存多个工作区配置，随时切换，互不干扰。比如"白天看盘"和"周末深度研究"可以是完全不同的布局。
- **启用大师子集**：在 Settings 里只勾选你信任的几位大师，共识计算时会自动把权重重归一化——不是简单平分，而是在你选的人之间重新分配权重。
- **委员会预设绑定 Profile**：切换 Profile 时，投委会页面的默认大师组合也一起切换。
- 配置保存在 `~/.augur/workspace.yaml`，支持导出/导入，换机器也能带走你的终端设置。

### Agent 可以操作你的终端

任何 MCP 客户端（Claude Desktop、Hermes、OpenClaw、Claude Code）现在都能直接读取和修改你的工作区配置，不需要你手动点 Dashboard：

```
mcp_augur_workspace_get        — 查看你当前的终端布局和启用的大师
mcp_augur_workspace_set        — 让 Agent 帮你切换预设、更新自选股或委员会
mcp_augur_workspace_profiles   — 列出、创建、删除、切换 Profile
```

### `augur_workflow` 一次调用跑完整分析链

```bash
augur workflow NVDA --steps fetch,analyze,consensus,committee
```

或者通过 MCP：`mcp_augur_workflow`。

一次调用串联 `fetch → analyze → consensus → committee → debate → sentiment` 多个步骤，任一步骤失败不会中断整条链，错误会单独记录到该步骤的结果里。

步骤默认跟随你的布局预设——`trader` 模式默认只跑 `fetch,consensus`，`committee` 模式默认多跑一步 `committee`。

### WebSocket 实时推送

- **`/ws/workspace`**：打开 Dashboard 时立刻收到当前工作区状态；任何修改（通过 API 或 MCP 工具）都会实时推送到所有打开的浏览器标签。
- **`/ws/workflow`**：逐步推送工作流进度——`step_start`（这一步开始了）、`step_done`（这一步完成了，结果在这里）、`done`（全部结束）。
- 首页 Dashboard 的 Ticker Tape 也是 WebSocket 驱动的实时价格流。

### 13 个 MCP 工具（新增 3 个工作区工具）

v10.0 在原有 10 个工具基础上新增了 3 个工作区工具（见上文），现在共有 13 个：

### 19 个 Hermes Skills + augur-terminal 元技能

每位大师都有独立的 Hermes 技能（`/skill augur-buffett` 等），中国大师全中文对话。新增 `augur-terminal` 元技能作为统一入口，涵盖 13 个工具、15 个页面、4 套预设的完整使用指南。

### Dashboard 体验改进

## v10.16.9 — OOS 验证（2026-06-xx，内部版本）

> 以下为内部迭代记录，已全部包含在 v10.0.0 中。

## 这次更新解决了什么问题

v10.16.8 解决的是 regime（牛/熊/震荡 × 高波动/低波动）检测本身"会不会因为单日噪声抽风"的问题，但当时明确留了一句话："`_REGIME_ADJUSTMENTS` 里那些手工设定的权重数字本身有没有用，从来没被验证过——留给后续 P2-4"。

这次（v10.16.9）就是去验证这件事：熊市高波动时把 Howard Marks 权重调高、把某些成长型 agent 权重调低，这些手工拍的数字，放到真实历史数据里跑一遍，到底有没有让预测变准？

**先说一个更基础的发现**：在动手验证之前发现，系统过去做历史回测时，从来没给过任何一天"真实的"财务基本面数据（PE、PB、ROE 等）——这些字段一直是 0。而像 Howard Marks、Benjamin Graham 这类价值风格的 agent，恰恰是靠这些基本面数字打分的。喂给它们的永远是 0，相当于给它们的分数钉死成了一个常数——常数分数不管怎么加权，排序都不会变。也就是说，在这次修复之前，"验证 regime 权重有没有用"这件事其实是**无法验证的**，不是没做，是做了也等于白做。

这次先补上了真实的、不偷看未来的历史财务数据（详见下文"点时财务数据"），然后才真正跑了验证。

## 验证结果

**结论：在 37 只股票、约 4.4 年的样本外数据上，regime 加权共识相比"平均权重"共识，没有看出稳定、一致的提升——五个 regime 桶里，提升或下降的幅度都很小，方向也不统一。**

这不是说这些权重数字"错了"，也不是说"验证通过了"——是这次终于把这件事老老实实测了一遍，测出来的结果是个"打平"。要不要保留、调整或者去掉这些手工权重，是后续的产品决策，这次不下结论。

更细颗粒度的"每个 agent 单独的横截面 IC"给出了更有信息量的方向性读数：在熊市高波动的这 9 天里，Benjamin Graham 的截面 IC 是 +0.086（符合"熊市要信 Graham"的假设），而 Howard Marks 是 -0.030（这 9 天里反向，与假设不一致）。这不是说 Howard Marks 没有价值，而是说在这两段特定的市场事件里，Graham 的信号比较有用，Marks 的没有表现出来——样本太少，没法推广成一般性结论。

需要额外说明的一点：熊市高波动这个桶，样本天数很少（37 只股票里，同一天至少有 5 只有真实财务数据覆盖的"熊市高波动"日，一共只有 9 天），而且这 9 天不是分散的，是集中在两小段连续的历史事件里（2024 年 8 月的日元套息交易平仓引发的抛售、2025 年 4 月的关税冲击抛售）。这种情况下算出来的置信区间只是个机械计算结果，不能当成有统计意义的证据——只能说这两小段历史时期方向上是这样，不能推广。统计上最有代表性的是震荡行情桶（n=746），那里 regime 加权与平权的差异是 +0.0009，几乎没有差别。

## 修复内容（验证过程中顺手发现并修复的两个 bug）

- **点时（point-in-time）财务数据**：新增了一套"历史回测专用"的财务数据获取逻辑——给定一只股票和历史上的某一天，只返回那一天"理论上已经能查到"的财报数据（年报通常要等财年结束后 1-3 个月才正式公布，这里统一按 90 天的保守滞后处理），绝不会偷看未来的财报。如果某一天确实查不到任何"已发布"的财报，就明确标记为"数据不足"，直接跳过那一天，而不是悄悄填 0 充数。
- **bug 1：雅虎财经的"最老一年"数据列有时是全空的，但之前会被误判成"有数据"**：雅虎财经返回的年报数据，最老的那一年一旦超出完整保留期，整列数值会变成空值（NaN），但列的"日期标签"还在。之前的逻辑只检查日期标签是否满足 90 天滞后，没检查这一列是否真的有数据——结果就是某些历史日期会"看起来正常"地返回一套全是 0 的财务数据，而不是正确地标记为"数据不足"。这正好是上面说的"无法验证"问题的另一个变种：本意是防止偷看未来和防止瞎填 0，结果在这个边界情况上两个问题都复发了。这次补上了"这一列必须真的有数值"的检查。
- **bug 2：雅虎财经接口本身会偶尔抽风，返回一次空结果，而旧逻辑会把这次空结果当真永久记住**：直接测试发现，同一只股票、同样的请求，连续三次在全新进程里调用，两次返回了正常数据，一次返回了完全空的结果——也就是说这是雅虎财经那一端本身偶发的不稳定，不是代码问题。但旧逻辑设计成"每只股票的财报只抓一次，抓到什么就永久缓存什么"，如果不巧第一次抓到的就是那次空结果，这只股票在整次运行里就会被永久误判为"没有财务数据"。这次改成了：如果第一次抓到空结果，会自动重试几次，只有重试后依然是空的才认定为真的没有数据。

## 测试情况

- 新增 `tests/test_pit_fundamentals.py`：16 个测试，全部离线、不联网、确定性可重复，全部通过。
- 完整测试套件 **2104 个测试全部通过**，没有失败项（这次改动前后都完整跑过一遍做对比，确认没有引入回归）。

## 这次没有做、以及没有下结论的地方

- 没有给出"regime 权重该不该用"的最终判断——这是产品层面的决定，这次只负责把数据和验证过程交出来。
- 熊市高波动这个桶的验证强度有限（只有两小段历史事件，9 个交易日），不能当成对"熊市该怎么加权"的一般性结论，只能当成对这两段具体历史时期的方向性观察。
